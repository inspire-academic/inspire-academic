## What this environment could and couldn't validate

This session ran on Windows with no Java, no Android SDK, and no
Xcode. That shaped what got proven here vs. what still needs Eric's
own machine:

- **Confirmed working here**: bundling the real site into `www/`,
  Capacitor config, and scaffolding *both* native projects
  (`npx cap add android` and `npx cap add ios`).
- **One assumption from the original research corrected by actually
  trying it**: the strategy doc's own research expected `cap add ios`
  to require macOS. It didn't — Capacitor 8's `add` step scaffolds a
  real Xcode project (`App.xcodeproj`) via Swift Package Manager
  (`CapApp-SPM/`), not CocoaPods, so no Ruby/CocoaPods/Xcode command
  line tools were needed just to generate the project structure. This
  is a genuinely more favorable finding than expected — worth noting
  since it means the *iOS scaffold* is buildable cross-platform now,
  even though *compiling and running* the app still requires Xcode on
  a real Mac (that part hasn't changed and wasn't tested here).
- **Not verified here, still needed**: an actual build. `android/app/
  build/` after `cap add android` is an empty placeholder
  (`.npmkeep` only) — no Gradle/Java ever ran. Reported "Syncing
  Gradle" in the CLI output was a lightweight internal step (copying
  config/plugin manifests), not a real `./gradlew build`. Getting a
  real APK requires Android Studio + a JDK on a machine that has them;
  getting a real iOS build requires Xcode on a Mac. Neither was
  attempted here since neither tool exists in this environment.

## The bundle itself

`scripts/build-capacitor-www.js` produces `www/` from an explicit
**include list** (not an exclude list — deliberately, so a new dev-only
folder added later can't silently leak into the shipped app just by
being forgotten from an exclusion rule):

Included: root `*.html` (except `mileiq.html` — CLAUDE.md flags it as
temporary/being removed), `manifest.json`, `sw.js`, `icons/`,
`assets/`, `resources/`, `projects/`, `teaching-lessons/`, `student/`,
`teacher/`, `parent/`, `tools/`, `subjects/`, `year6/`, `programmes/`,
`assessment-engine/`.

Excluded (confirmed by content, not assumed): `node_modules/`,
`tests/`, `docs/`, `design-reference/` (grepped — zero live HTML files
reference it; these are unlinked design mockup images), `scripts/`,
`supabase/`, `netlify/` (Functions are called over HTTPS from the live
domain — never bundled as static files), `property/` (CLAUDE.md:
private, moving to its own repo), plus the usual `package.json`/
`netlify.toml`/`CLAUDE.md`/`.git`/`.claude`.

**Result: 171 files, 42MB** — a normal, unremarkable size for a native
app bundle. This is the concrete number behind "~95% code reuse":
essentially the entire real site, unmodified, ported as-is.

## A real bug this spike caught

`cap add` copies `www/` into *each platform's own* asset folder
(`android/app/src/main/assets/public/`, `ios/App/App/public/`) — so
committing `android/`/`ios/` naively would have put **three full
copies of the same 42MB site** into git (the original plus one per
platform, ~126MB total). Fixed in `.gitignore`: those two
platform-owned copies are excluded the same way `www/` itself is —
regenerated by `cap sync` (which re-runs the copy from `www/`), never
committed as if they were source. What's actually tracked under
`android/`/`ios/` after this fix: **655KB** of genuine native-project
source (Gradle files, `AndroidManifest.xml`, Xcode project files, app
icon/splash placeholders) — the only things a native Android/iOS
project actually needs version-controlled.

## Re-running this spike / keeping www/ current

`www/` is gitignored and regenerated on demand:

```
node scripts/build-capacitor-www.js
npx cap sync
```

`cap sync` re-copies `www/` into both native projects and updates
their native dependency manifests — run it after any web-side change,
before opening either native project.
